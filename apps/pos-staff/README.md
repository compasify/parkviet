# ParkViet Staff

The Flutter app for staff devices. One installation is paired with one
branch and runs in the mode the POS dashboard gives the device: waiter,
kitchen display, runner (expo), kiosk, owner, bridge or print station. The
print station is complete; the other modes open a placeholder.

Built with Flutter 3.32.5 (Dart 3.8). Package versions are the newest that
resolve on that SDK; raise them together with the SDK.

## Run it

```bash
flutter pub get
flutter run
```

The app needs a running Spree API (`pnpm spree dev` in the repository root).
Pair a device from the welcome screen, either by scanning the QR code the POS
dashboard shows for a new device, or by typing the server address and the
pairing code:

- An Android emulator reaches the host as `http://10.0.2.2:3000`.
- A phone or tablet on the LAN uses the host's LAN address, for example
  `http://192.168.1.10:3000`.

The address must be `http` or `https`. Plain `http` to a LAN address is
allowed by the platform only where its network rules allow it.

A device in waiter or owner mode asks a person for their name and PIN. The
other modes work as the device itself. Holding the title bar for three
seconds and entering a manager's PIN opens device management, which shows the
pairing and can unpair the device.

## The API client

`packages/pos_api` is generated from `server/openapi/pos-staff.yaml` with
openapi-generator (dart-dio, built_value). Do not edit it by hand.
After changing the contract:

```bash
bash tool/gen_api.sh   # needs Node (npx), Java 11+ and dart on PATH
```

The generator version is pinned in `openapitools.json`, its settings are in
`tool/openapi-config.yaml`, and `tool/templates` holds the generator template
that is overridden. CI regenerates the client and fails when it differs from
the committed one.

App code generated by freezed, riverpod and the localizations is committed
too. Regenerate it with `dart run build_runner build`.

## Tests

```bash
flutter analyze
flutter test
flutter test --update-goldens   # after a deliberate change to printed bytes
```

The ESC/POS tests render the print documents in
`server/spec/fixtures/print_documents` and compare the bytes with
`test/goldens`.

`integration_test/app_test.dart` runs against a development server on a
device or emulator; the values it needs are listed at the top of the file.

## Printing

A print station claims the jobs of the printers bound to it, prints them and
reports each attempt. It supports:

- `escpos_lan`: raw TCP, port 9100 unless the address says `host:port`.
- `escpos_bluetooth`: Bluetooth Classic (SPP) on Android, and BLE printers on
  Android and iOS. Pair the printer in the system settings first and store
  its address as the printer's Bluetooth id.
- `sunmi_builtin`: the printer inside a Sunmi device.

The printer's `codepage` setting `bitmap` prints text as images, so every
Vietnamese letter prints on a printer without a Vietnamese code page. Other
values print text without marks. `cut: false` leaves out the paper cut.
Labels in TSPL are sized to their content.

On Android the station keeps the screen on and runs a foreground service.
iOS stops the app in the background, so a print station on iOS must stay open
on screen.

## Release signing

### Android

Keep the upload keystore outside the repository. Create
`android/key.properties` (ignored by git) next to it:

```properties
storeFile=/absolute/path/to/parkviet-staff.jks
storePassword=...
keyAlias=upload
keyPassword=...
```

`flutter build apk --release` or `flutter build appbundle` then signs with it.
Without the file, a release build is signed with the debug key, which works
for testing but cannot be published.

### iOS

Open `ios/Runner.xcworkspace` in Xcode, choose the team under Signing &
Capabilities for the Runner target, and use a provisioning profile for the
bundle id `vn.parkviet.parkvietStaff`. CI builds with `--no-codesign`.
