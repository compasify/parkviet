# POS administration

`CLAUDE.md` imports this file. This standalone Vite + React app administers POS
configuration; it does not run selling, shifts, printing or inventory workflows.

## Run and verify

Run the API through `pnpm spree dev --no-open` from the repository root. Never
invoke Rails, Ruby, rake, bundle or Docker Compose directly. In this directory:

```sh
pnpm install
pnpm dev             # strict port 5176
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm test:e2e        # API fixtures, desktop/tablet/mobile; sequential workers
```

## Structure and integration contract

- `src/routes/`: TanStack file routes and access guards. `routeTree.gen.ts` is
  generated by Vite's router plugin; do not hand-edit it.
- `src/pages/`, `components/`, `tables/`, `schemas/`: resource UI, reusable controls,
  table definitions and form schemas respectively.
- `src/hooks/`: Admin API wrappers. Use `posRequest`, which delegates to the
  registered `adminClient.request`; never use POS session coordinator or fetch
  directly. All query keys begin `['pos', storeId, resource, ...]`.
- `src/lib/pos-access.ts`: store permission keys + selected-branch capability gates.
  Each protected route must use `PosRouteGuard`; hiding nav is not authorization.
- `src/nav.ts`: registrations only, synchronized from the same access predicates.
  6.0.3 `settingsNav` has no `if`; unavailable entries are not registered.
- `src/i18n.ts`, `locales/{vi,en}.json`: every visible string is translated.
  POS keys are registered in both `translation` and `pos`; shell keys live under
  `posDashboard`. Core i18next initialization must not be replaced.

Import framework components/providers from `@spree/dashboard-core`, controls from
`@spree/dashboard-ui`. Keep core/ui/admin-sdk pinned together at **6.0.3**.
Pure POS logic comes from `@parkviet/pos-shared/<module>`; shared data types are
under `@parkviet/pos-shared/types/pos-context` and `types/print-adapter`.

Use `usePosSession()` inside the store shell for `{context, selection, setSelection}`;
`context` is a React Query result, selection is `{branchId, registerId}`. Explicit
`usePosContext(selection)` and `useBranchSelection(branches)` are also available.
The context API returns **bare** JSON, while list/mutation endpoints generally
return `{data, meta}`. Never blindly unwrap every SDK response.

The store SDK header is set in route `beforeLoad`, before child queries run.
PermissionProvider mounts **inside** StoreProvider. Do not move it above the store
or reuse a previous store's permissions. Auth uses refresh cookies, not localStorage
tokens; logout clears the framework query cache.

Writes use `useMutation`/`useResourceMutation`; preserve 409 reason and 422 field
details so shared failure helpers and `mapSpreeErrorsToForm` still work. Destructive
click actions need `useConfirm({variant:'destructive', ...})`. Invalidate the current
store's POS keys after writes. Never embed SDK entity types inside form-value types.

Do not edit `apps/dashboard`. Do not remove old POS configuration routes until
the new equivalents pass E2E and the cutover phase is explicitly authorized.
